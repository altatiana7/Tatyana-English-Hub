# Память и лимиты: что делать с весом репозитория

Короткий ответ: **сейчас вам ничего не грозит**. За размер репозитория GitHub
не блокирует — он присылает предупреждения и просит уменьшить. Отключают Pages
за другое: когда сайт используют как файлохранилище с большим трафиком.
Но подготовиться стоит: деплой заливает 612 МБ на каждый push, а `.git` уже
разросся до 448 МБ.

---

## Лимиты GitHub и ваше положение

| Лимит | Значение | У вас | Запас |
|---|---|---|---|
| Файл в репозитории | предупреждение от 50 МБ, блокировка от 100 МБ | максимум 31 МБ | ок |
| Размер опубликованного сайта | 1 ГБ | 612 МБ | 39 % |
| Сборки Pages | 10 в час | 2–3 на push | ок |
| Трафик Pages | ~100 ГБ/мес (мягкий) | 600 МБ × ~165 открытий | зависит от класса |

Самый крупный файл — `maya-course/media/ef5e-preint-pe1-main.mp4`, 31 МБ
(после сжатия). До блокировки в 100 МБ далеко.

деплой секунды, лимит 1 ГБ забыт навсегда.

## Куда переносить медиа

| Вариант | Бесплатно | Подходит для |
|---|---|---|
| **Supabase Storage** | 1 ГБ | аудио уроков, карточки |
| **Cloudflare R2** | 10 ГБ, без платы за исходящий трафик | крупные аудиокурсы |
| **YouTube (unlisted)** | без ограничений | видео; ссылку видит только тот, кому дали |

Аудио остаётся доступным по прямой ссылке — для учеников ничего не меняется,
кроме того, что файл грузится не с GitHub.

## Порядок работ

1. **Видео** (63 МБ) — выложить на YouTube, вставить `<iframe>`.
   Это самый простой шаг и самый заметный выигрыш.
2. **`spotlight-*`** (284 МБ) — загрузить mp3 в Supabase Storage,
   в страницах заменить `audio/v01.mp3` на внешний адрес.
3. **`card-audio`** (67 МБ) — перенести в Storage; `card-audio.js` уже строит
   путь из `BASE`, достаточно поменять одну константу.

Каждый шаг обратим: старые файлы остаются в истории git, поэтому откат —
это `git checkout` конкретного файла, а не восстановление из бэкапа.

## Бэкапы: чтобы точно не пропало

GitHub — не резервная копия. Репозиторий можно случайно испортить, а доступ —
потерять. Минимум, который закрывает риск:

| Что | Как | Как часто |
|---|---|---|
| Планнер | кнопка «Копии…» уже пишет файл в папку | каждый день автоматически |
| Папка планнера целиком | копия на флешку или Google Drive | раз в месяц |
| Репозиторий | `git bundle create hub.bundle --all` → на Drive | раз в месяц |
| Или просто | скачать ZIP репозитория с GitHub | раз в месяц |

`git bundle` создаёт один файл со всей историей — его можно хранить где угодно
и восстановить командой `git clone hub.bundle`.

## Что уже сделано

* медиа сжато: 892 → 612 МБ (видео −128 МБ, аудио −105 МБ, дубли −38 МБ);
* `.gitignore` не даёт случайно закоммитить локальный планнер и бэкапы;
* планнер убран из публичного репозитория — его данные больше не публикуются.

## Чего опасаться не стоит

* «Забанят за размер» — нет, GitHub не блокирует за объём репозитория.
* «Пропадёт история» — репозиторий публичный, копия есть на GitHub и у вас
  локально; плюс бандлы из таблицы выше.
* «Ученики потеряют доступ к урокам» — уроки остаются на Pages, адреса
  не меняются.
