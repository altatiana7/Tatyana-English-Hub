## 2. Что сделано

### Приватность

* `<meta name="robots" content="noindex,nofollow">` добавлен на **192** страницы
  (было 30) — теперь на всех 222;
* `robots.txt` в корне закрывает сайт целиком и отдельно `*.pdf` и `/tools/`;
* `noindex` в мета-теге работает даже там, где `robots.txt` игнорируется
  (Яндекс, прокси-краулеры), поэтому дублирование намеренное.

> Это защита от поисковиков, а не от людей. Ссылка всё равно открывается у
> любого, кто её знает. Репозиторий публичный — см. раздел 4.

### Деплой

* добавлен `.nojekyll` — legacy-сборка больше не пытается обрабатывать файлы
  с пробелами и скобками;
* добавлен workflow `check-links.yml` — проверка ссылок на каждый push и PR.

**Требуется действие владельца:** Settings → Pages → Source → **GitHub Actions**.
Через API переключить нельзя (403), а пока стоят обе схемы, каждый push
запускает две публикации и одна из них падает.

## 4. Что осталось и почему

### 4.1. Переезд на приватный хостинг — рекомендация №1 по риску

Репозиторий публичный: любой, кто знает адрес, видит имена учеников, тексты
домашек и суммы оплат в планнере. `noindex` закрывает только поисковики.

Варианты:

* **Cloudflare Pages** + Cloudflare Access (почта в allowlist) — бесплатно до
  500 сборок/мес, приватность без своего сервера;
* **Netlify** + встроенный password protection (платная опция, $19/мес);
* оставить как есть, но убрать из публичных страниц телефоны, адреса и суммы.

Это решение владельца, поэтому автоматически не делалось.

### 4.2. Медиа всё ещё 500 МБ

Сжатие дало −32 %, но архитектурно проблема в другом: в git лежит 20 часов
аудио и видео, которые не являются кодом. Дальнейшие шаги:

* длинные видео — на YouTube (unlisted) + `<iframe>`, из репозитория удалить;
* 30 файлов `*-brief-check/audio/v*.mp3` — это 245 МБ, вариативная озвучка
  уроков; при следующей генерации просить TTS сразу в 32–48 кбит/с;
* при переезде на Cloudflare Pages лимит 1 ГБ снимается (лимит файла 25 МБ,
  общий размер проекта — без жёсткого потолка).

### 4.3. Копии курсов ЕГЭ

`ege-2027-b2-katya`, `ege-2027-b2-rita`, `ege-teachers-hub`,
`katya-ege-teacher-8m3q`, `rita-ege-teacher-0vop` — пять почти одинаковых
наборов страниц (97 МБ). HTML различается мало, аудио у учеников своё.
Правка урока вносится до пяти раз вручную, и копии уже разошлись
(в одной из папок нет `audio/mock1-l39.mp3`).

Полный рефакторинг на общие ассеты не делался сознательно: слишком высокий
риск сломать живые уроки в середине учебного года. Безопасный следующий шаг —
скрипт `tools/sync-lesson.py`, который переносит урок из «мастер»-папки в
папки учеников и показывает diff перед записью.

### 4.4. Pull request #3 «Teaching Progress»

Открыт с 27 октября, 3 файла, +1082 строки: одна самодостаточная страница
`teaching-progress/index.html` + два тестовых файла. Ветка отстала от `main`
на 20 коммитов, но конфликтов не будет — добавлена только новая папка.

Замечания по ревью:

* данные демонстрационные, хранятся в `localStorage` — на разных устройствах
  журнал будет разным; баннер об этом на странице есть;
* ссылки на учеников заданы абсолютными адресами
  (`https://altatiana7.github.io/...`), при смене домена сломаются;
* имена учеников подставляются в `innerHTML` без экранирования — для одного
  пользователя это самовредительство, не уязвимость, но правится в одну строку.

Функционально дублирует часть `teacher-calendar/planner-v2.html`. Решение —
за владельцем: влить как эксперимент (не ссылаясь с главной) или закрыть.
